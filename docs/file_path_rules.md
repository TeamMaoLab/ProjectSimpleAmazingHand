# 项目文件路径规则

为了确保项目在不同环境下的可移植性和一致性，特别是在使用 Git 进行版本控制时，我们制定了以下文件路径规则：

## 1. 相对路径原则
所有代码中的文件路径都应使用相对路径，而不是绝对路径。这确保了项目在不同用户的机器上能够正确运行。

### Python 脚本中的相对路径
在 Python 脚本中，应使用 `os.path` 或 `pathlib` 模块来构建相对于脚本位置的路径。例如：
```python
import os

# 获取当前脚本所在目录
script_dir = os.path.dirname(os.path.abspath(__file__))

# 构建相对于脚本的文件路径
file_path = os.path.join(script_dir, "data", "example.xml")
```

## 2. 文档中的路径引用
在 Markdown 文档中，使用相对路径来引用项目内的其他文件。例如：
- 引用同级目录下的文件：`[链接文本](./filename.md)`
- 引用子目录下的文件：`[链接文本](./subdirectory/filename.md)`
- 引用上级目录下的文件：`[链接文本](../filename.md)`

## 3. 项目结构
项目应保持清晰的目录结构，常见的目录包括：
- `src/` 或 `scripts/`：存放源代码或脚本
- `data/`：存放数据文件
- `docs/`：存放文档
- `archive/`：存放历史文件或归档内容
- `tests/`：存放测试代码

## 4. 版本控制
- 所有源代码和文档都应纳入 Git 版本控制。
- 大型二进制文件（如模型文件、数据集）应考虑使用 Git LFS（Large File Storage）进行管理。
- 生成的文件（如日志、临时文件）不应纳入版本控制，应添加到 `.gitignore` 文件中。

遵循这些规则可以确保项目在不同环境下的一致性，并便于团队协作和版本管理。
